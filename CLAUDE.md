# Maltipoo (питомник мальтипу) — how we work

Static HTML/CSS/JS site built from Figma, page by page. No framework. Node is used only for local tooling (generators, image/font/CSS/JS builds, Lighthouse). The browser loads plain files. If the site later moves to WordPress, the static pages stay the reference (see "WordPress port").

> Keep this file current: update the status table, the components list, "Deviations from Figma" and "Content flagged to the client" after each piece of work.

Single-language site (Russian): no `src/` + `i18n/` build; `index.html` is edited directly. Originals live in `../maltipo-originals/` (`figma/` full-frame screenshot, `figma-assets/` MCP downloads, `figma-exports/` node renders, `images/` named sources for `npm run build:images`).

## Project structure

```
index.html  <other pages>.html
css/normalize.css  css/style.css  css/media.css  css/vendor/*.css   → built into css/site.min.css
js/main.js         js/vendor/*.js                                    → built into js/site.min.js
assets/fonts  assets/icons  assets/images  assets/images/decor
tools/        generators and build scripts (Node/Python, project-local)
lighthouse/   saved reports: lighthouse-<name>.json/.html
package.json  devDependencies only (pinned exact versions); node_modules/ is git-ignored
../<project>-originals/   originals outside the deployable project (Figma PNG exports, font files)

Multilingual sites (see "Languages"):
src/index.html             the template: default-language text inline + data-i18n keys (edit this)
i18n/<lang>.json           translations    i18n/config.json  (languages, phone/WhatsApp, siteUrl)
index.html <lang>/index.html   generated by tools/build-html.mjs — never edit
```

New project setup:
- Copy from the previous project: `tools/` (`scale-laptop.py`, `build-css.mjs`, `build-js.mjs`, `optimize-images.mjs`, `lighthouse.sh`, `lh-summary.mjs`, and `build-html.mjs` for multilingual sites), `package.json` (scripts + pinned devDependencies), `.gitignore`, and the host config (`vercel.json`, `.vercelignore`). Then `npm install`.
- Adjust in the copies: CSS/JS source lists, browser `targets` in `build-css.mjs`, the originals path (`IMAGES_SRC`), and `tools/images.config.json` (starts empty: widths are measured per image).
- Set up the browser MCP servers (see "Browser testing") and check that they are connected (`claude mcp list`) before relying on browser checks.

Hard rules:
- Source CSS: desktop styles → `style.css`, all responsive overrides → `media.css`, vendor CSS in `css/vendor/`. No per-page CSS files.
- Source JS: only `js/main.js` (vanilla JS, no jQuery). Every feature is an `initX()` that returns early if its elements are missing, so one file serves all pages. Hook into markup with `data-*` attributes, not with styling classes.
- **The page links only the bundles** (`css/site.min.css`, `js/site.min.js`). After editing any source run `npm run build`. Never edit a generated file; every generated file starts with a "Generated by … Do not edit" banner.
- On a multilingual site the HTML pages are generated too: edit `src/*.html` + `i18n/*.json`, never `index.html` or `<lang>/`.
- Static hosting with no build step on the host (e.g. Vercel `framework: null`, empty install/build commands, `outputDirectory: "."`): commit the generated files, and keep sources and tooling off the site with an ignore file (`.vercelignore`).
- Vendor libraries are local files in `*/vendor/`, pinned to an exact version, never loaded from a CDN. New npm packages: pinned exact (`--save-exact`), and at least two weeks old.
- Header, footer and any announcement bar have identical markup on every page. Change one, change them all.
- Reuse existing components, tokens and assets before adding new ones. Before saving a Figma export, check for duplicate images by md5 (`md5 -q file`).
- Colours, gradients, radii, container width, easing and fonts are CSS custom properties on `:root`. No magic hex values in components.
- Inline `<script>` is allowed only in `<head>` for things that must happen before the first paint (e.g. `--fixed-vh`, an animation "pending" class). Keep each to one line and explain it in a comment.
- Never commit unless the user asks.

- Figma MCP is the source of truth. Workflow per frame:
  1. `get_metadata` on the frame → section list and positions.
  2. `get_design_context` (screenshot on). For a big flat frame, `forceCode: true` on the whole frame works; otherwise per section.
  3. `get_screenshot` at 1:1 (`maxDimension` = frame height) and slice it to compare section by section.

- **Flat frames** (no section groups): derive the section boundaries from the layers (backgrounds, image tops), write them down as a section map in this file (`Figma y → section, height`), and position children section-relative (`top = figmaY − sectionTop`).
- **Hidden and covered layers:** skip layers that are hidden, or fully covered by a later opaque layer. List them under "Deviations from Figma".
- **Rotated layers:** `get_metadata` x/y of a rotated node is NOT its bounding box; the generated code's wrappers are. Recreate a rotated element as one element centred on the bbox centre with `transform: rotate()`.
- **Masks on rotated layers:** the MCP's `mask-size` is the mask's bounding box, but the mask PNG is the unrotated shape (PNG size ÷ 2). Solve the unrotated window from the bbox: `W = (BW·cos − BH·sin) / (cos² − sin²)`, `H = (BH·cos − BW·sin) / (cos² − sin²)`, centred on the bbox centre. Then build the "card + window + photo" as one rotated element with an `overflow:hidden` window. Check that W×H matches PNG/2.
- **Opaque rectangular masks** (photo crops) are equivalent to an `overflow:hidden` box with the image offset inside. Check the mask alpha before choosing.
- Download MCP assets with curl, **including the file extension** in the URL (asset URLs expire after 7 days). Strip `preserveAspectRatio="none" overflow="visible" style="display: block;"` from SVGs, except where an SVG must stretch (e.g. a full-width curve), and say so in a comment. Remove the preview background rects from exported logos.
- Figma sometimes clips text with fixed-height frames, stretches images, has typos, inconsistent spacing, copy-pasted labels or duplicated numbering between frames. Don't copy those bugs. Show the full text, keep images undistorted, and tell the user about every deviation.
- **Text wrapping:** where Figma breaks lines differently from what its box width would give, it uses hard breaks. Reproduce them with hideable `<br class="…">`, not with tweaked widths. Measure text widths in the browser before choosing a box width.
- **Rendered vs box position:** occasionally Figma renders glyphs offset from the text box (mixed line-height spans). Match the rendered position, and note it.
- Missing content (draft copy, placeholder contacts, missing links) goes in "Content flagged to the client".

## Typography

- Fonts: Helvetica Neue 400/500/700 (body), Felidae (display words, as SVG), Mr Dafoe (®, as SVG). Licence: none supplied — Helvetica Neue comes from the system via `local()` with the Figma metric overrides (Arial elsewhere). Without a web licence, use the system font via `local()` and flag it; never download fonts from unofficial sources.
- **Match Figma's vertical metrics:** Chrome draws Helvetica-like fonts ~0.1em lower than Figma. Wrap the font in `@font-face` with `ascent-override`/`descent-override`, solved so that the cap top sits at the text-box top. Verify on ~10 text blocks by finding the first white/ink pixel row in Figma vs the browser screenshot (within 1px). The overrides are % of font-size, so they work for any file of the family. Safari ignores them.
- **Self-hosted webfonts:**
  - WOFF2 only; `font-display: swap`; preload only the weight of the LCP text.
  - Subset to Latin (`fontTools.subset`, Google "latin" ranges, `--layout-features='*'`, keep hinting). Check coverage of every character the page can show, incl. `text-transform: uppercase` and JS messages.
  - Keep the originals outside the project.
  - Add a second `@font-face` family with `local()` and the same overrides as the fallback while loading, so the swap moves nothing on devices that have the font.
- **Check supplied font files** (fontTools): family/style names, weight class, units per em, vertical metrics, licence/copyright fields, glyph count. Then compare text widths against the reference font in the browser (per weight, min–max ratio). Files from mixed editions are common; flag any weight that is off by more than ~0.5%.
- **Check character coverage per language before translating** (fontTools `getBestCmap()` on the originals, per weight): accents (ã ç é ñ ¿ ¡), Cyrillic, €. Supplied files often miss whole scripts in one weight (e.g. a "Cyr" edition with Cyrillic but no accented Latin). Fill the gaps without new downloads where possible:
  - Extra `@font-face` rules for the same family and weight with a `unicode-range`, declared after the main face (a later face wins for the characters in its range).
  - `src: local("<system name>"), url(<a file the page already loads>)`: Apple devices use the system font; other devices reuse a cached file.
  - Script subsets (e.g. Cyrillic, 5–11 KB per weight) as separate files with `unicode-range`: only pages that use those characters download them.
  - Flag the remaining compromise to the client (the official licensed set fixes it).

## Breakpoints (`css/media.css`)

| Range | Approach |
|---|---|
| ≥1920px | Desktop, exact Figma values (`style.css`) |
| 1280–1919px | Laptop: every px value × 0.75, `--container: 1440px`. **Generated**, see below |
| 768–1279px | **Tablet: a layout of its own** (client request: no scaled mobile frame). Hand-written block at the end of `media.css`, sub-steps 1024–1279 and 768–999 |
| ≤767px | Compact (phones): the mobile Figma frame × `--m` (= width / 360) |
| ≤480px | `--m: 1` — exact mobile Figma (no-JS fallback values) |
| ≤359px | `--m: <320/360>` — narrow phones |

- Order of work per page: 1920 → laptop ×0.75 → mobile frame → tablet (from the tablet frame if it exists, otherwise from the mobile frame scaled).
- No `transform: scale()`, `zoom` or vw-based layout sizing. Scale factors are CSS custom-property multipliers (`calc(Npx * var(--m))`).
- In `media.css`, the shared blocks for each breakpoint come first, page-specific blocks after. Label every block with a comment.
- **Laptop ×0.75 is generated** (`tools/scale-laptop.py`): it copies every declaration with px values from `style.css` × 0.75, keeps 1px hairlines and borders, and replaces only the block between `/* laptop:generated:start */` and `/* laptop:generated:end */`. Hand-written laptop overrides go after the end marker: images sized only by HTML `width`/`height`, and 1px lines that must stay on whole pixels. Never edit inside the markers.
  - **New components need a laptop check, not only 1920.** The generated block copies base shorthands (e.g. `.field { border: 1px solid white-15 }`) after your modifier, so a modifier that only changes a colour (`.field--light { border-color: wine }`) silently loses on 1280–1919. Add a hand-written override after the end marker. Images sized by HTML attributes in new components (logo, close icon, decor circles) also need laptop sizes there, or a centred logo ends up off-centre.
  - Compact blocks often reset generic classes (`.btn`, `.field`) after the component rules; give component overrides two classes (`.popup__form .popup__field`) so they win without `!important`.
- **Horizontal anchors** (so layouts survive viewports narrower than the scaled frame, e.g. 1280 < 1440):
  - Left half → `left: figmaX`.
  - Right half → `right: frameW − figmaX − w`.
  - Centred → `left: calc(50% ± …)`; its container needs `left:0; right:0`.
  - Elements that must stay next to each other (e.g. cards and the photos beside them) use the same anchor.
  - Full-bleed decorative layers align to the design frame with `left: calc(50% − var(--container) / 2)`.
- **Tablet layout (768–1279), the rules:**
  - Sections in normal flow (flex / grid). Desktop rules position children absolutely with 1920 values: reset them with `position: relative; inset: auto` and lay them out; widths `auto` + `max-width` on text, never `<br>` (all `br` are hidden on tablets).
  - Fixed type and spacing between the mobile and laptop sizes (titles 40–60px, body 16px), gutter `--t-pad` (32px, 40px from 1024), cards and buttons keep their desktop size where they fit (catalog puppy card, why/delivery/care cards, `.btn`).
  - Composite cards whose parts must keep their proportions (the catalog grid card) scale with one factor (`--pc`), not the page.
  - Photos that carry text get a dark (or card-coloured) gradient under the text; decor that has no room (eyes / visit pills, contact-card puppy, the docs logo below 1024) is hidden.
  - Desktop 2-class rules (`.cat-hero--about .cat-hero__title`, `.growth--about …`, `.graduates--short …`) need 2-class tablet overrides.
  - Images: mobile crops are `media="(max-width: 767px)"`; tablets get the desktop files. Sliders: `SLIDERS[name].tablet = { gap }` (default 20) at 768+.
  - Checked at 768 × 1024, 834, 1024 × 768, 1180, 1279 (overflow sweep + screenshots).
- **Compact layout from the mobile frame (phones ≤767):**
  - Every value is the Figma mobile value written as `calc(Npx * var(--m))`. Horizontal positions are offsets from the centre (`calc(50% ± N * var(--m))`, N = figmaX − frameW/2), so content forms a centred column of `frameW × m` with full-bleed backgrounds.
  - Full-screen blocks (hero) anchor their text to the screen edges instead.
  - Collages can spread wider than the column with a separate factor (`--spread`).
  - Buttons and form fields keep their own (unscaled) size; only their placement scales.
  - Write the block as a template with `m(N)` / `c(N)` macros and expand it with a script; it avoids hundreds of hand-typed `calc()`s.
- Sections with decor wider than the viewport: `overflow-x: clip` (not `hidden`, which would also clip anything poking out vertically).
- A `<br>` that gets hidden on smaller screens must have a space before it in the HTML (`text <br>more`). Design-only breaks: `<br class="br-design">` (hidden below desktop) / `<br class="br-compact">` (hidden on desktop).
- **Hero = one screen:** `height: var(--fixed-vh)`, set in `<head>` from `innerHeight`, and updated in JS only when the width changes (mobile toolbars must not make it jump). Pin the title to the top and the bottom elements to the bottom with Figma's distances; add a `min-height` so they never collide on short screens.
- Before a page has its real tablet or mobile design, it may rely on "Interim fixes" blocks that only stop horizontal overflow. Delete them when the real design lands.
- **Layout that survives other text** (new labels, other languages); build it this way from the start:
  - **Buttons:** `min-width` = the Figma width, plus `padding-right` that reserves the ring/arrow area, so a longer label widens the pill instead of running under the icon. For centred text left of an icon, add the same padding on both sides so the centre stays.
  - **Centred elements whose width can grow:** `left: 50%; translate: -50% 0` (the individual property composes with animation transforms).
  - **Big titles with fixed boxes:** `width: min-content; min-width: <Figma width>`. The box widens only when a single word is longer than it; right-anchored titles grow to the left.
  - **Lists and columns** (menus, footer links): size to content (`max-content`, `height: auto`), not to the Figma box made for the original item count. Gradient text (`background-clip: text`) is invisible outside its box, so the box must cover every item.
  - **Icons next to a word** (sparkles, stars): inline after the text (`display: inline-block`, `white-space: nowrap`, the Figma gap as `margin-left`), never absolutely positioned at a fixed offset that only fits one label. Reset a base `img { display: block }` rule.
  - **A flex row with a decorative rule and a link:** the rule `flex: 1 1 0` between a min and its Figma width, the text `flex: none`, and the row `flex-wrap: wrap`. The rule gives way first, and an over-long link moves down whole instead of breaking mid-phrase.
  - **Single long words that cannot wrap** (one word per line in a big title): a per-language font size with `:lang(xx)` on the breakpoints where it doesn't fit. Hard line breaks inside a word-group (`Рио-де-<br class="br-compact">Жанейро`) belong to the translation, not the template.
  - **An icon inside a circle that changes size per breakpoint** (e.g. a 61px circle on mobile after a ×0.75 laptop block): reset the icon's size and offsets on that breakpoint too, or it sits off-centre.
  - **Boxes wider than the screen in the Figma mobile frame** (e.g. a 400m heading box on a 360 frame): narrow them to the text column, or longer text runs past the screen edges.
- **Zooming out a cropped photo on phones** (clients often find the Figma mobile crop too close):
  - Scale it down around its focal point: `left: calc(50% − <focal x fraction> × <width>)`, and keep the bottom edge where the design anchors it.
  - A photo that must cover a full-screen block gets `height: max(<scaled height>, var(--fixed-vh) + 8px)`, `width: auto`, and `left` derived from the height × aspect ratio.
  - Check landscape tablets separately; restrict the change to phones (`≤768`) when the smaller photo no longer covers the wider screens.
- **iPhone Safari can fade a blurred layer at the clipped screen edges** (blurred gradient "haze" + `overflow:hidden` parent), and the page background shows as thin side strips. Put an unblurred copy of the same gradient (same size and position) behind it.

## Components and patterns

Document each shared component here when you create it: class names, modifiers, `data-*` hooks, the `init` function, and the Figma node id.

- **Icons:** SVG masks, `<span class="icon icon--name" aria-hidden="true">`. They take their colour from `currentColor` and their size from `--icon-size`. One SVG file per icon in `assets/icons/`.
- **Buttons:** `.btn` plus modifiers (`--primary/--outline/--white/--ghost`, sizes `--md/--lg/--xl`). Colours via custom properties (`--btn-color`, `--btn-fill`, `--btn-hover-fg`). Per-instance width and padding come from a layout class, never from a new button class. Widths are `min-width` (see Breakpoints → "Layout that survives other text").
- **Language switcher** (multilingual sites): `PT | EN | ES | RU`-style links with `hreflang`, `lang`, and `aria-label="PT, Português"` (keeps the visible code in the accessible name). The current page has `aria-current="true"` (set by the build). It stays visible in the mobile header beside the burger (unscaled, ~12px), not only inside a menu. Shrink the burger if it doesn't fit at 320.
- **Hovers:** short transitions (0.3–0.55s, one easing token).
  - Fill effects use a `::before` layer (e.g. `clip-path: circle()` growing from the icon). The element's own background moves to an `::after` layer that fades out after the fill, to avoid an anti-aliased rim.
  - Never put a hover transition on an element that also carries a scroll-animation attribute (see Animations).
- **Forms:** `novalidate`, each field in a `.field-wrap` (positioning + animation target).
  - Rules in one `VALIDATORS` map picked by `data-validate`.
  - Error text inside the field (`aria-describedby`, `aria-invalid`), shown on blur when something was typed and on submit; it clears live while fixing. Focus goes to the first invalid field.
  - Success state in a `role="status"` line.
  - Without a backend, say so in the code and in "Content flagged". With one, see "Lead forms, CRM and ad tracking".
  - Read the form's endpoint with `form.getAttribute('action')`: a field named `action` (WordPress admin-ajax needs one) shadows `form.action`.
  - One `initForm(form)` for every `[data-booking-form]` (footer, menu, popup); messages come from `data-msg-*` on each form. On success the form dispatches a custom event (`booking:sent`) so a container (a popup) can switch to its thank-you state.
  - **Error text inside the field must fit any language:** a fixed `padding-right` (e.g. 130px) is too small for long messages (ES "Nombre demasiado corto" is 142px at 12px). Set the field's inline `padding-right` to the measured message width + its right offset + ~10px when it appears, clear it when it goes, and make the placeholder transparent while the error shows. Test the longest message per language in the narrowest field.
- **Custom dropdown:** `[data-dropdown]` root (maltipoo: the list fades and slides in with `.is-open`, 0.3s, and gets `hidden` back 300ms after closing; the contacts form list opens upwards, `.ct-form .dropdown__list { bottom: calc(100% + 6px) }`), a toggle with `aria-expanded`/`aria-controls`, and a `role="listbox"` menu with `role="option"` items. The value lives in the root's `data-value`, and the component fires `change` on the root. It closes on outside click and on Esc, and supports arrow keys.
  - Inside a form: the value goes to a hidden `input[name]`. `form.reset()` does not clear a hidden input set from script; listen to the form's `reset` event and restore the placeholder text yourself.
  - Keyboard: on open, focus the listbox (`tabindex="-1"`) and track the active option with `aria-activedescendant` (↓/↑/Home/End, Enter/Space choose, Esc closes and returns focus to the toggle, Tab closes). Turn off the listbox's own focus outline (a global `:focus-visible` rule frames the whole list) and mark the active option instead.
  - Option labels: reuse existing translation keys (service names, menu items); keep values language-independent (`bridal`, `other`).
  - A narrow field cuts long choices: ellipsis on the value plus a `title` with the full name.
  - The open wrapper needs `z-index` above the following fields when they carry scroll animations (each transformed wrap is its own stacking context).
- **Mobile menu / drawers:** a toggle with `aria-expanded`, a backdrop, and Esc to close. Lock page scroll while open (and stop smooth scroll, if it's used).
- **Modals (full-screen menu, popups) share one helper**, `createDialog(el, { panel, focus, onOpen, onClose })`:
  - Markup: `role="dialog" aria-modal="true"`, `hidden` while closed; a fixed overlay and the cross carry `[data-dialog-close]`. CSS animates `.is-open` (overlay fade, panel fade + rise, staggered links); `hidden` is set again after the closing transition (~500 ms, 0 with reduced motion).
  - Behaviour: Esc and `[data-dialog-close]` close; Tab is trapped in the panel; focus goes to the first link/field and returns to the element that opened it. Scroll lock: `html.is-dialog-open { overflow: hidden }` + `lenis.stop()/start()`.
  - **Low windows scroll the dialog, they don't shrink it** (clients prefer it): the dialog is `position: fixed; inset: 0; overflow-y: auto; overscroll-behavior: contain` with `data-lenis-prevent` (Lenis checks it before its stopped state, so the wheel still scrolls the dialog). The overlay is `position: fixed` so it covers the screen while the panel scrolls.
  - **Centred popups:** the dialog is a flex container with padding and the panel has `margin: auto`: centred both ways when it fits, scrolling from the top when it doesn't (unlike `align-items: center`, which cuts the top off).
  - **Full-screen menu panels:** on desktop the panel follows the window (`height: max(100vh − margins, <Figma height>)`); on phones give it `height: auto` (content + bottom padding), or it stretches into a tall empty sheet on tall screens.
  - Links inside a menu close it first, then the normal anchor handler scrolls. Buttons that open a popup keep their `href` as the no-JS fallback (`data-popup-open`, `aria-haspopup="dialog"`) and the anchor handler skips them.
  - **Success state in the same popup:** fade the form out with `visibility: hidden` (it keeps the panel's height) and fade an absolutely centred thank-you layer in; switch `aria-labelledby`, focus its title (`tabindex="-1"`, no outline); a "Go back" button closes; every opening resets to the form. Keep the cross above that layer (`z-index`).
  - A Figma menu often has fewer links than the site: use the site's list centred on the same point, and move the blocks below by the extra rows.
  - **Long translated links in a mobile menu:** allow wrapping (`white-space: normal`) and keep a wrapped link visually one item: a tighter line-height plus vertical padding that adds back up to the Figma line (e.g. 49.5 = 36.3 + 2 × 6.6), so single-line items don't move.
- **Inner-page banner:** one shared hero class plus a per-page modifier. Per-page differences go through custom properties (e.g. `--hero-overlay`), not duplicated rules.
- **Page background patterns** (grid, texture):
  - Put them on **one wrapper** around everything between the banner and the footer, never per section. Sections inside stay transparent.
  - Spacing under the banner goes on `.hero + .wrapper` (padding-top), so the pattern starts right at the banner edge. Offset the pattern so it opens the way the design does.
  - A gradient that spans two sections: give both the same `background-size` and offset `background-position`.
- **Gradient text:** `background-clip: text` + `color: transparent`. No transforms on its children: a transformed child can drop out of the clip.
- **Dismissible bars and notices:** remember "closed" in `sessionStorage`, not `localStorage`.
- **Cart and other state:** frontend only, exposed as one global (`window.<Project>Cart`). Keep it to the current page's DOM.

## Animations and smooth scroll (if used)

- **Scroll animations (e.g. AOS):** set the attributes in `main.js` from one `ANIMATIONS` list (selector, effect, delay, stagger, duration, offset), not in the HTML. Re-run refresh after showing, hiding or reordering content (and on `load`). Nothing inside tabs or sliders animates. Respect `prefers-reduced-motion` (then set no attributes at all).
  - aos.css overrides `transition-property/duration/delay` of the animated element, so hover transitions go on its children or pseudo-elements.
  - AOS delays exist only in 50 ms steps; there is no `fade-in` (use `fade`).
  - Built-in AOS effects overwrite `transform`. For elements with their own transform (tilted cards), write custom effects with the individual `translate`/`scale`/`rotate` properties; they compose with `transform`.
  - The last items on the page need `offset: 0`, or they sit below the trigger line at max scroll. Clip the footer (`overflow:hidden`) so start offsets don't make the page taller.
- **Never animate the LCP element from `opacity: 0`** (Chrome ignores it for LCP). Set a "pending" class in `<head>` that holds it at `opacity: 0.01` until the animation takes over. Add fallbacks: remove the class if the library is missing; add a CSS animation that shows it after ~3 s.
- **Scroll-linked effects** (parallax, scrub, text fill) share one loop, `addScrollEffect({ measure, update })`:
  - `measure()` reads geometry in page coordinates only on init, resize, `load`, `fonts.ready` and a ResizeObserver.
  - `update(scrollY, vh)` only computes and writes; no layout reads per frame. Use `offsetTop` for elements that move themselves.
  - Run it inside the smooth-scroll library's tick (same frame), plus a rAF-throttled native `scroll` fallback.
  - Write styles only when they change; animate only compositor properties (`translate/scale/rotate/opacity`) with `will-change`.
  - Keep each effect's numbers in one config object in `main.js` (e.g. `{ selector, start, end, angle }` as viewport fractions). Breakpoint-specific timing goes in a nested override (`compact: { media: '(max-width: 1279px)', start, end }`), picked in `measure()` with `matchMedia`.
  - Scrubs work in both directions: a positive `x` slides in from the right, a negative one from the left.
- **"3D" from a single photo** (no 3D model, no new assets, compositor-only). Clone the element's `<picture>` in JS (same URL, so a cache hit), animate the clone, and leave the original as the base. At rest the clone must be pixel-identical to the photo (angle 0, or hidden), so the design stays untouched:
  - **Opening lid** (a case or box photographed open):
    - The clone is cut at the hinge line (a box `height = width × hingeY/photoW`, measured in `measure()`); the original is `clip-path`-ed below the hinge.
    - The lid rotates `rotateX(<closed angle> → 0)` around its bottom edge, with `transform-style: preserve-3d` and `backface-visibility: hidden` faces. Its back face (the outside of the lid, not in the photo) is drawn in CSS: tokens for velvet/leather, gold corners, piping, a clasp.
    - `perspective-origin` above the box (e.g. `50% -40%`) matches a photo shot from above, so the closed lid is seen from above. On small screens use a longer perspective and a higher origin, or the closed lid swells past the screen.
    - At full open, add a class that hides the lid and removes the clip.
  - **Spinning object** (a ring or wreath of products on a plain background):
    - The clone gets a soft circular `mask-image: radial-gradient(...)` around the object (opaque past its farthest pixel, faded beyond) and rotates around the object's centre (`transform-origin` in % of the photo). Measure the centre and maximum radius from the original with sharp (pixels that differ from a blurred background).
    - Angle 0 when the section's centre is at the viewport centre, ± with the scroll. A little `rotateX/rotateY` with `perspective()` adds depth.
    - **Limits:** the object must stay inside the photo's inscribed circle around its centre (the distance to the nearest edge), and a background gradient turns with the clone, so a seam grows with the angle. Calculate which angles are actually visible while the object is on screen, and check those.
  - **The clone's own transform:** if the photo is positioned with `transform` (e.g. `translateX(-50%)` for centring), read `getComputedStyle(base).transform` in `measure()` and prepend it to the clone's transform, or the clone jumps.
  - **Parallax:** give the clone the same class as the photo and create it before the parallax init, so both move identically.
  - **Text on the animated object** (e.g. labels printed over the lid): fade it in at the end, and only where it really sits on the object. If the mobile layout puts it elsewhere, leave it to its normal entrance animation.
- **Transforms create stacking contexts.** Any bar that holds a dropdown or popover gets `position: relative; z-index: <n>`.
- **Smooth scroll (e.g. Lenis):** use its own rAF loop if `autoRaf` is missing; keep native scroll in inner scroll areas (`data-lenis-prevent`); stop it while a drawer or modal is open; route in-page `#` links through `lenis.scrollTo` (with the sticky header's offset); don't start it with reduced motion.

## Images

- **Originals stay outside the project** (`../<project>-originals/images/`), never edited or served.
- `tools/optimize-images.mjs` (sharp) builds `assets/images/<name>-<width>.webp` (+ `.avif`) from `tools/images.config.json`:
  - Never upscale.
  - Quality is adaptive per variant, judged by PSNR against the original at the same width: WebP q90 → 94 → 97 → 100 until ≥ 42 dB; q100 is accepted at ≥ 40 dB, otherwise near-lossless.
  - AVIF (4:4:4) at the lowest quality reaching the WebP's PSNR (capped at ~44 dB); an image gets AVIF only if the whole set is smaller.
  - Call `sharp.cache(false)`, or re-encoded files are measured from cache.
- **Widths** = the CSS size each `<img>` actually needs at every breakpoint (cover crops included: `max(w, h × aspect)`) × 2, plus × 3 on phones, capped at the original. Measure them in the browser with iframes per breakpoint; don't guess.
- Markup: `srcset` with `w` descriptors and `sizes` with one entry per breakpoint (`100vw` for full-bleed). AVIF via `<picture><source type="image/avif" …><img …webp…></picture>` with `picture { display: contents }`; any `.x > *` rule also gets `.x > picture > img`.
- The LCP/hero image: eager, `fetchpriority="high"`. Everything else: `loading="lazy" decoding="async"`. CSS background textures: crop to the visible part (lossless).
- **Verify quality:** render the old page (original PNGs) and the new one at 2× and compare screenshots by PSNR per region (≥ 40 dB). Look at zoomed side-by-side crops. Make sure animation states match before blaming compression.

## Build and performance

- `npm run build` = `build:css` (laptop generator + lightningcss bundle) + `build:js` (vendor + esbuild-minified `main.js`).
  - lightningcss needs explicit `targets` (the oldest browsers the CSS already needs). Without them it drops `-webkit-backdrop-filter` (Safari < 18). It also drops the unprefixed property when the `-webkit-` one comes after it in the same rule: write the prefixed one first (vendor CSS too). After a build, check that prefix and unprefixed counts in the bundle equal the sources, and make the build script fail if they don't.
  - Several page bundles (shared `base` + one per template) beat one site bundle once pages differ a lot: each page links `base` + its own. Pick the bundle per template, not per URL, so a CMS can choose it the same way.
  - Scroll-animation CSS stays render-blocking (inside the bundle). Loading it late shows elements, then hides them for their entrance.
- **Lighthouse:** `npm run lh -- <name> [mobile|desktop]` (headless Chrome, JSON + HTML into `lighthouse/`), `npm run lh:summary -- a.json [b.json]`.
  - The runner reuses whatever already listens on its port. If another project's server holds it, Lighthouse audits the wrong site: check `lsof -i :<port>` (or the page title) first and use the port override (`LH_PORT=8791 npm run lh -- …`). Never kill a server that isn't yours.
  - Mobile uses simulated throttling (Lantern): every request that starts before the observed LCP counts against the LCP. Fewer early bytes (smaller images, subset fonts) is what moves it; preloads and priority tweaks usually don't.
  - Simulated LCP varies ±1.5 s between identical runs: compare **medians of 3 runs**, and A/B a change by toggling only that change.
  - `python3 -m http.server` sends no `Cache-Control`; caching is a hosting setting (write the rules for the actual host).
- Keep a "tried and rejected" list here, with numbers, so nobody repeats it.
- **Images: ask before multiplying files.** A responsive set (widths × formats) can turn 60 images into 600 files; some clients want the originals plus one AVIF each. Agree on the scheme first, and keep a JPEG/WebP fallback only where AVIF support matters.

## WordPress port (if the site moves to WP)

A custom theme built from the finished static site. The static pages are the reference: the WP output must render the same.

- **Local stack:** Docker Compose with `wordpress` + `mariadb` + a `wpcli` service (profile, run on demand), on a fixed port. Mount the theme folder, the static `assets/` into the theme (one source of CSS/JS/images for both sites), plugins, `mu-plugins/`, and root files the static site links (`favicon.ico`, PDFs). Secrets live in a git-ignored `.env`, with a committed `.env.example`.
- **Templates map one-to-one to page types:** `header.php`/`footer.php` from the shared partials, `front-page.php`, page templates per layout (`template-<name>.php`), a custom post type for repeated items (cases, products) with `archive-<cpt>.php`/`single-<cpt>.php`, `home.php`/`single.php` for the blog, `404.php`. Write the map down before cutting.
- **Content fields in code:** register ACF field groups with `acf_add_local_field_group` in the theme (versioned, no DB export). Data that repeats in the static HTML (cases, posts, page blocks) becomes fields, not hard-coded markup.
- **Seeding:** extract content from the static HTML into JSON (`theme/inc/seed/*.json`) and load it with a WP-CLI command (`wp <project> seed [pages|posts|…]`). It must be idempotent (update by slug, never duplicate), so the whole site can be rebuilt from scratch.
- **URLs match the static site:** set the permalink structure (trailing slash or not) to the static URLs, give the CPT the same base path, and keep slugs. Every old URL must answer 200 or have a 301.
- **Media:** a static site has no thumbnails. Turn off intermediate sizes (`intermediate_image_sizes_advanced` → `[]`) and the "-scaled" copy (`big_image_size_threshold` → `false`); allow AVIF uploads if the site uses them. Output the same `<picture>` markup as the static pages.
- **Make WP stop changing the markup:**
  - `wptexturize` off (`run_wptexturize` → false): it rewrites quotes and dashes, so text stops matching.
  - Remove emoji scripts, RSD/WLW links, oEmbed discovery, generator tags, global styles / block library CSS, and plugin CSS the theme replaces.
  - `language_attributes` filter for the right `<html lang>`.
- **Assets:** enqueue the same bundles with `defer` (`wp_enqueue_script` strategy), version by file mtime, keep the head scripts (`--fixed-vh`, font preload) as they are. Pick the page bundle from the template.
- **Forms:** keep the static markup and JS validation. Submit via `admin-ajax.php` (`action` + nonce) to a handler that passes the data to the form plugin's API (e.g. `GFAPI::submit_form`), so entries, notifications and add-ons still work. Map plugin fields by admin label, not by numeric ID. Add a honeypot field.
- **Plugins:** use what the client already runs elsewhere when it fits (fewer things to learn). Keep plugin files out of git; record names and versions in the README.
- **Verify the port, not just the pages:**
  - Static vs WP comparison per page: element signatures (tag, classes, text, key attributes) in order, plus computed styles. Expected differences are listed in a script allow-list (hidden form inputs, fixed typos), everything else is a bug.
  - Run the same UI check and Lighthouse scripts with a `WP=1` switch against the WP URL.
  - Test the real form flow end to end, then delete the test entries everywhere they landed (form plugin, CRM, chats). Form plugins may reject test domains such as `example.com`: use a real-looking address.
- **Migration:** a script that exports DB + uploads (or an All-in-One-style archive) and a script that replaces the local domain with the production one (`wp search-replace`, serialized-safe). Never edit the DB by hand.

## Lead forms, CRM and ad tracking (if used)

The chain: **form → form plugin entry → CRM lead → notifications → ad platforms**. Each link must fail without breaking the previous one: a CRM or Telegram outage never loses a lead or the visitor's "thank you".

- **Push to the CRM after the form plugin has saved the entry** (e.g. `gform_after_submission`), inside `try/catch` that only logs. The entry is the backup.
- **Idempotency:** store the form entry ID on the lead (`wpGfEntryId`-style field) and check it before creating, so double submits and retries make one lead. Turn off the CRM's own duplicate check (it usually matches by name and rejects a returning client's second request).
- **Typed CRM fields vs free text:** phone numbers parsed as international numbers, dates, enums. Normalise first (phone → `+375…`); if the CRM still rejects a field, drop that field, put its raw value into the description, and retry (bounded loop). A lead with a wrong-format phone is still a lead.
- **Leads without a name** (phone-only forms): name the lead by the phone so it is readable in lists and notifications.
- **Attribution:** a small script stores UTM tags, `gclid`, `fbclid`, `_fbp`/`_fbc`, landing page and referrer in a first-party cookie on the first visit, and adds them as hidden fields on submit. The server copies them onto the lead.
- **Webhooks from the CRM** (status / stage changes):
  - Verify the signature (HMAC of the raw body) against every configured secret; `permission_callback` stays open only because of that.
  - Payloads often carry only the ID and the changed field, and don't say which event fired: use a separate endpoint per event (e.g. "lead created" vs "status changed").
  - Take the new status/stage **from the webhook**, not from re-reading the record: the queue runs later, and the record may already have moved on.
  - Always answer 200 once the signature is valid (errors go to the log), or the CRM retries forever.
  - Webhooks are queued by the CRM's cron (minutes, not seconds). From a CRM container to a local WP, use `host.docker.internal`.
- **Notifications (Telegram):** bot token and chat ID in `.env`. Group chat IDs are negative (`-…`); supergroups start with `-100`. If the CRM is the main path, send the "new lead" message from the CRM webhook and use a direct message from the form only as a fallback when the CRM is not configured, so nothing is sent twice.
- **Ad platforms:**
  - Browser event and server event (Meta Pixel + Conversions API) share one `event_id` so they count once. Fire the browser goals (Pixel `Lead`, GA4 `generate_lead`, Metrika goal) from one `CustomEvent` that the form script dispatches on success.
  - CRM-born events (qualified lead, closed deal) are `action_source: system_generated`, timed at the moment they happen (Meta rejects events older than 7 days), and sent once (store "sent at" on the record).
  - Send only with marketing consent; hash personal data as the platform requires.
  - Integrations without keys yet stay in the code as dormant placeholders that skip silently when their keys are empty.
- **CRM setup as code:** a provisioning script (fields, statuses, pipeline stages, currency, webhooks, API user) so a fresh CRM can be rebuilt. Set the currency list before using a non-default currency, or amounts are rejected.
- **Secrets:** every key and token in git-ignored `.env` files. A token pasted into a chat or ticket is compromised: rotate it before production.

## SEO and structured data

- **Per page:** unique Title ≤ 60–65 characters, description 70–160, one H1 containing the query, self-referencing canonical, OG image. Commercial queries in one city want the city in Title and H1.
- **Close duplicates on a CMS:** delete demo content ("Sample Page", "Hello world"), `noindex, follow` on author, date, search and default-category archives, keep taxonomies nobody uses out of the sitemap, and 301 paginated archives that duplicate one page.
- **Schema (JSON-LD, one `@graph`, through the SEO plugin's filters when there is one):**
  - Organization as the specific subtype (`ProfessionalService`, `ClothingStore`…) with address/city, phone, email, `areaServed`, `priceRange`, `contactPoint`.
  - Blog posts: `BlogPosting` with the organization as author when there are no real authors (drop the auto-generated `Person`), `wordCount`.
  - FAQ blocks: `FAQPage` + `Question`/`Answer` built from the same data the page shows.
  - Service pages with prices: `Service` + `Offer` (price, currency); a services overview: `OfferCatalog`; portfolio items: `CreativeWork`.
  - Never mark up what the page doesn't show (prices, reviews, ratings).
- **SEO plugins don't see custom-field content** by default: feed the field text into their analysis (e.g. Yoast `wpseo_pre_analysis_post_content`).
- **Audit script:** crawl the sitemap plus internal links and probe the usual duplicate URLs (`/author/…`, `/category/…`, `/page/2`, `?s=`, `?p=`), then report status, robots, canonical, Title/description length, H1 count, missing alt, invalid JSON-LD, thin pages (< 150 words in `<main>`), duplicate titles/descriptions and indexable pages missing from the sitemap. Rerun it after every SEO change.
- **Strategy document** (`SEO-PLAN.md`): indexed pages, competitors and their prices from the real market, one intent → one URL keyword map, cannibalisation, blog audit, priorities P0–P4, article briefs, facts to confirm with the client, order of work. Search tools may not show the target country's results: say so and check against Search Console / Yandex Webmaster. ## Languages (if the site is multilingual)

- **Architecture: separate static pages per language**, generated from one template (`tools/build-html.mjs`, `npm run build:html`, part of `npm run build`). Not a JS text swap: separate pages are indexed per language (`hreflang` + canonical + `x-default`), show no default-language flash before the swap, and keep LCP unchanged.
  - Paths: `/` default language, `/<lang>/` the others. Subfolder pages get `../` in front of `assets/`, `css/`, `js/` (rewrite `src`/`href`/`srcset` in the build). Language links are root-relative (`/pt/`). Set the production domain (`siteUrl`) so hreflang URLs are absolute.
  - Template markers:
    - `data-i18n="key"` replaces the inner HTML (allow `<br class="…">` and entities);
    - `data-i18n-attr="attr:key;attr:key"` replaces attributes (alt, aria-label, placeholder, meta content, form messages);
    - `data-whatsapp-text` becomes a `wa.me/<number>?text=<encoded>` link;
    - a `<!-- i18n:alternates -->` comment becomes the hreflang block.

    Strip the markers from the output.
  - **The build stops when a language misses a key** and warns about unused keys. It writes `i18n/en.json` (every key with the default-language text) as the reference for translators.
  - **JS has no per-language strings.** Form errors and confirmations go in `data-msg-*` attributes on the form (translated like any attribute, with a default-language fallback in JS). Labels for live text are `data-*-label` attributes. Formats follow `<html lang>` (e.g. 12-hour time in English, 24-hour elsewhere).
- **First visit:** an inline `<head>` script on the default-language home page redirects (`location.replace`) to the first supported language in `navigator.languages`, otherwise it stays. A choice made in the switcher is saved (`localStorage`) and always wins. Direct links to `/<lang>/` are never redirected.
- **Switching keeps the place:** on click, save the choice and add the hash of the section on screen (the last `section[id]` whose top is above ~40 % of the viewport) to the link.
- **Canonical and hreflang must be absolute URLs** (Lighthouse SEO fails relative ones). Keep a `siteUrl` in the language config and set it as soon as the production domain is known (the hosting's default domain works until then); generate `robots.txt` and a `sitemap.xml` with the hreflang alternates from the same config.
- **Language codes:** Brazilian Portuguese `pt-BR`, Latin-American Spanish `es-419`. Decide formal vs informal address per language and write it into the JSON `_note`.
- **Translations written by Claude:** say so in "Content flagged to the client" and ask for a native speaker's proofreading before launch. Keep brand lines (logo) in the original; translate the h1 and its repeats consistently.
- **Layout per language:** follow "Layout that survives other text" (Breakpoints), and check fonts first (Typography → coverage). Then check every language at every width (How to verify → step 4).
  - Typical failures: buttons, lines indented by the design (a stepped title's last line holds ~12 characters), single long words in big titles, link columns, long legal links.
  - Rebalance the lines in the translation (shorter wording) before shrinking the type.

## Accessibility baseline

- Semantic landmarks (`header`, `nav`, `main`, `footer`) and one `h1` per page (repeated titles elsewhere are `p`).
- Every control is a real `<button>` or `<a>`.
- Icon-only buttons have an `aria-label`. Decorative icons and images have `aria-hidden="true"` or `alt=""`.
- Use `aria-expanded`/`aria-controls` on toggles and `aria-live="polite"` / `role="status"` on status text that changes.
- Focus states are visible (`:focus-visible`, also for hover-only effects). Everything works from the keyboard (Tab, Enter/Space, Esc, arrow keys in listboxes).

## Browser testing (Chrome → Safari → Firefox if needed)

Order: **Chrome first, then Safari. Firefox only when it is needed.**

1. **Chrome** (`chrome-devtools` MCP + Lighthouse) is the main workbench. Every step of "How to verify" runs here first: positions vs Figma, the overflow sweep, emulation, performance traces, Lighthouse. Fix everything in Chrome before moving on.
2. **Safari** (`safari-mcp`, Apple's official `safaridriver --mcp`, Safari 27+) comes after Chrome is clean, for every change that touches layout, fonts, CSS effects or JS. Check:
   - console errors;
   - failed requests (navigate twice: the first navigation of a session records no requests);
   - `CSS.supports` for whatever the change uses;
   - images (`currentSrc`, none broken after a full scroll);
   - fonts (`document.fonts` status);
   - overflow at the sweep widths;
   - animations after a full scroll;
   - forms;
   - screenshots at 1440, 1024 and 360.
3. **Firefox** (`firefox-devtools` MCP, Mozilla's official `@mozilla/firefox-devtools-mcp`) is **only when needed**: a Firefox bug is reported, the change uses CSS/JS with patchy Gecko support, Chrome and Safari disagree, or the pre-launch check. Same checklist as Safari. It adds a debugger (scripts, logpoints) and the Firefox profiler.

Setup (once per machine, `local` scope; never remove or overwrite existing servers):
- Chrome: from the ECC plugin (`chrome-devtools-mcp@<pinned version>`).
- Safari: in Safari, turn on Settings ▸ Advanced ▸ "Show features for web developers", then Settings ▸ Developer ▸ "Allow remote automation and external agents". Then run `claude mcp add safari-mcp -- /usr/bin/safaridriver --mcp`.
- Firefox: `claude mcp add firefox-devtools -- npx -y @mozilla/firefox-devtools-mcp@<pinned version> --tool-preset developer`.
  - **No `--profile-path`:** every session gets a fresh temporary profile. Never connect it to the personal profile.
  - **Never** use the `mozilla`/`all` presets (privileged tools).
- Restart Claude Code after adding a server; until then its tools are not available in the session.

Limits:
- **Safari:**
  - The viewport is the real window: the page area is ~130px shorter than requested and the minimum width is 336.
  - DPR is fixed at 2; no touch, no CPU throttling, no Lighthouse; network timings are empty; no CLS/INP entries.
  - It ignores `ascent-override` (text sits ~0.1em lower).
  - Every new session starts without a tab, so navigate first.
- **Firefox:**
  - The minimum window width is 500 (no phone widths).
  - `saveTo` paths must stay inside the working folder.
  - `profiler_stop` writes the profile into `~/Downloads`; delete it afterwards.
- **Safari (continued):** `evaluate_javascript` has a 30 s limit, so split long scripted checks into several calls. Screenshots can come back blank; pass `savePath` (scratchpad) and crop with `sips` to inspect details.
- **Chrome:** `take_screenshot` with `filePath` must point inside the workspace roots; otherwise take it inline (JPEG, and a lower `deviceScaleFactor` for long pages).
- **Phones:** none of the three covers real touch, the moving toolbar or a real GPU. Use Chrome emulation for layout, plus a real iPhone (Safari Web Inspector over USB) before launch.
- **Scripted scrolling with smooth scroll (Lenis):** after `scrollTo` the page keeps easing. Repeat `scrollTo` until the target holds and wait ≥ 1 s before reading scroll-linked values; values read too early look like the effect running backwards.
- **CSS entrance animations** (e.g. a hero image scaling from 1.08) inflate measured sizes for a few seconds; wait or account for them.
- **Cookie banners hide from automation:** vanilla-cookieconsent does not show when `navigator.webdriver` is true. Override it in an `initScript` (`Object.defineProperty(Navigator.prototype, 'webdriver', { get: () => false })`) to test the banner; answer it from the keyboard so Safari stays in focus-ring mode.
- **Shell (zsh):** unquoted `$VAR` does not word-split, so `for x in $LIST` and `set -- $pair` loops break. Use arrays, functions or separate calls; macOS has no `timeout` command.
- **Language detection:** test it with `initScript` overriding `navigator.languages`, in a fresh isolated context (`new_page` with `isolatedContext`), so earlier saved choices don't interfere.
- Report per browser what was checked and what wasn't.

## How to verify (every change)

Steps 1–8 run in Chrome; then Safari (and Firefox when needed) as described in "Browser testing".

1. Run `python3 -m http.server 8765` in the project folder (Lighthouse runs stop it; restart before browser checks). Stop it afterwards with `pkill -f "http.server 8765"`.
2. Rebuild first (`npm run build`), then reload with `ignoreCache`; stale files cause false alarms.
3. Positions: measure with `offsetLeft/offsetTop` chains (not affected by animation transforms) and compare to Figma, per breakpoint: 1920 exact, 1440 = ×0.75, 360 = mobile frame. Pin the hero height with an `initScript` setting `--fixed-vh` to the Figma height for exact comparisons.
4. Horizontal overflow (`scrollWidth > width`) and overlapping text boxes, at 1920, 1440, 1280, 1279, 1024, 960, 769, 768, 600, 480, 390, 360, 359 and 320px: sweep with iframes of each width. Also check real glyph extents (`Range.getClientRects`), ignoring elements that haven't animated in yet.
   - **`scrollWidth` misses clipped text.** Sections with `overflow: hidden/clip` cut off text that runs past the screen without making the page scroll. Also flag every text range whose box goes past `0…width`, or past the text column on mobile.
   - **Multilingual:** run the sweep for every language and compare each with the default language (scripts off: sandboxed iframes). Flag:
     - text boxes that overlap only in the translation;
     - text spilling out of its own box;
     - a button label reaching its icon or leaving the pill;
     - clipped or off-screen text.

     Then look at screenshots of the hero, dense text sections, cards and the footer in the longest languages at 390/360/320. Also check the default language against itself after label changes.
5. Refactors that must not change rendering (bundling, minifying, `<picture>` wrappers, font swaps): compare every computed property (or every element box/text width) between old and new in **sandboxed iframes without scripts** (deterministic, animation-free) at several widths. Exclude custom properties (only their text form changes).
6. Performance: `chrome-devtools` emulate with `viewport` **and** `cpuThrottlingRate` in the same call (a CPU-only call resets the viewport). Run a rAF `scrollTo(y += 30)` loop and record frame deltas plus `long-animation-frame` / `layout-shift` entries. A trace shows forced reflows as `UpdateLayoutTree`/`Layout` nested in `FunctionCall`.
7. Interactive parts: open dropdowns, menus and drawers, and use `document.elementFromPoint` at their centre to confirm they're on top. Test reduced motion and "library missing" by overriding `matchMedia` / `window.<Lib>` in an `initScript`.
   - Dialogs: every opener on every language page; Esc, overlay, cross and links close; focus returns to the opener; the page behind doesn't move; a low window (e.g. 1920 × 620, 360 × 600) scrolls the dialog; the panel matches Figma at the frame size (1920 × 1197, 360 × 913).
   - Forms: empty submit, the longest error message per language in the narrowest field, the success state, and the reset afterwards.
   - Safari runs no transitions in a background window: check end states there with `* { transition: none !important }` injected, and judge the animation in Chrome.
8. Regression: page height and positions at the widths already designed stay the same; the console has no errors (a missing `favicon.ico` 404 is harmless; errors from your own sandboxed test iframes are expected).
9. Report deviations from Figma honestly, along with what was verified and what wasn't. Nothing is committed unless the user asks.
